# Docker Best-Practices Audit — workspace vs. Bret Fisher's Node-in-Docker rules

**Date:** 2026-07-12 · **Scope:** all 18 workspace repos with a Docker setup · **Standard:** `Docker_Edited/DOCKER_SYSTEM_PROMPT.md` (Bret Fisher, DockerCon 2017–2023 + DockTalk) · **Method:** read-only, one auditor per repo, every violation cited at file:line.

**Totals:** 11 HIGH · 45 MED · 22 LOW across 18 repos. But the raw count is misleading — read the two framing findings first, because most of the MED count collapses into one architectural fact.

---

## The two findings that explain most of the report

### Finding A — the ScriptHammer family ships a DEAD production stage (8 repos, the dominant pattern)

Every ScriptHammer-family app (ScriptHammer, SpokeToWork, TurtleWolfe, HogBall, eightysix, RescueDogs, HatCoatAndBoots, chattanooga-mini) sets `output: 'export'` in `next.config.ts` — they're **static sites deployed to GitHub Pages**, with no running Node server. But they all inherited a Next.js **`runner` prod stage** that does `COPY --from=builder /app/.next/standalone` and `CMD ["node", "server.js"]`. Under `output: 'export'` those artifacts (`standalone`, `server.js`) are **never produced**, so:

- `docker build --target runner` **fails at the COPY** (or the container exits instantly with "Cannot find module server.js").
- This is dead/vestigial code from the upstream template, not a security hole. The *dev* target is what actually runs, and it's well-built.

This single mismatch generates ~15 of the 45 MED findings (NEXTJS_STANDALONE ×9, MULTISTAGE_PROD ×several, plus the SIGNAL_HANDLING flags on that unreachable stage). **The fix is one decision per repo, not fifteen:**
- **Either** delete the `runner`/`builder` prod stages entirely (honest: these are static-export apps, the container is dev-only, prod is GitHub Pages), **or**
- **switch** `next.config.ts` to `output: 'standalone'` if a Node server image is genuinely wanted (then the runner stage works and Tini should be added).

Do it once in ScriptHammer and propagate to the forks — which leads to Finding B.

### Finding B — the family has DRIFTED (6 distinct Dockerfile variants across 8 forks)

The forks are no longer in sync. Two of eight (**ScriptHammer, HatCoatAndBoots**) still expose the `runner` prod stage as a real build target (`prod_target=yes`); the other six are effectively `dev-only`. **HogBall has drifted the furthest and worst** — its dev stage comments out `USER node` and runs as root via an `su node` entrypoint (see HIGH findings). The base image is the one thing they all still agree on: **`node:22-slim` everywhere** (bookworm-based, Bret-approved — the hardest rule, and they pass it uniformly).

**Recommendation:** pick the best family Dockerfile as the canonical one and reconverge. **Template-Library is the actual gold standard** in the whole workspace (see below) — its pattern (real standalone prod target, Tini PID1, `node server.js`, `USER node`, `--chown`) is what the family *should* look like if it wants a working container prod target.

**Highest-leverage fixes (fix once, help many):**
1. **Resolve Finding A in ScriptHammer, propagate to 7 forks** — clears ~15 MED at once.
2. **Add a `.dockerignore` that excludes `.env*`, `Dockerfile*`, compose, tests** to the ~10 repos missing it — one template, dropped everywhere.
3. **Add db healthchecks + `condition: service_healthy`** to the compose files that gate an app on a database.

## Bottom line

- **Nothing is on fire.** After verifying every HIGH, there's **no confirmed leaked live secret** and **no production service running insecurely** — the scary-looking secret findings are demo defaults, placeholders, or gitignored files.
- **The real work is 3 leveraged fixes:** resolve the dead-Next.js-runner-stage (Finding A) in ScriptHammer and reconverge the drifted family on it; drop a proper `.dockerignore` across ~10 repos; add db healthchecks where an app waits on a database.
- **Individual must-fixes:** HogBall's `USER node` (runs as root), RedWood-Blog's shell-form prod CMD (signal handling), and hello-world-ai's alpine+root (if it's ever more than a scratchpad).
- **Your gold standard already exists:** **Template-Library** scored a clean 0/0/0 and is textbook Bret Fisher. Point the family at it.
